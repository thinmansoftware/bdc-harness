## Scope and cases

- Exactly four cases: positive, shell, patch, code-mode. Each has independent unique ownership.
- No Claude/Fable, account auth, provider endpoint, purchases, application feature implementation, merge or runtime activation.
- Real SDK plus pinned CLI; only synthetic API key and loopback endpoint differ from the closed fixture options. No caller-selected options, model, catalog, endpoint or flag builder API.
- Complete parsed installed Linux entry must equal the frozen original, including defaults; duplicate keys, extra fields and multiple selected entries reject. Retain whole Linux output hash separately from source fixture hash.
- Capture bounded decoded request, complete instructions and tools/framing hashes. Reject unknown request fields and every executable tool/namespace/extension definition; omitted empty tools may be legitimate.
- Inspect effective app-server config and empty MCP/plugin/skill catalogs; do not infer effective controls from accepted syntax.
- Hostile response calls are recorded by the fixture endpoint independently of raw SDK events. Require explicit denied tool output, no successful result, no sentinel effect and no accepted verdict. Resource/protocol failure is failure, not denial.
- No compaction, output reserve, real reviewer quality, account/Linux-model entitlement or laptop readiness claim.
